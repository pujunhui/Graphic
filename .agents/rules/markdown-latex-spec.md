# Markdown 与 LaTeX 数学公式编写规范（100% 兼容 GitHub Web 与主流预览器）

在本仓库创建或编辑任何 Markdown (`.md`) 文档时，必须严格遵守以下排版与公式规范，以彻底杜绝 GitHub Web (`cmark-gfm` + MathJax) 及本地预览器中的公式渲染失败、矩阵换行丢失或字符图错位问题。

---

## 一、行内公式（Inline Math：`$ ... $`）五条铁律

1. **外侧必须留白（最关键！防中文/全角标点粘连失效）**：
   - 在 GitHub 的 `cmark-gfm` 解析器中，中文汉字与中文全角标点（`：`、`，`、`。`、`（`、`）`、`、`）不被视作 ASCII 标点，而是被当作普通单词字符。若 `$` 紧贴全角字符（如 `分量：$f_x = 1$` 或 `（$w=1$）`），GitHub 会判定 `$` 位于单词内部从而**直接放弃渲染**。
   - **规范**：开头的 `$` 左侧必须有**半角空格**（或位于行首），结尾的 `$` 右侧必须有**半角空格**（或位于行尾）。
     - ❌ 错误：`沿 X 轴分量：$f_x = L_{xz}$，其中（$w=1$）。`
     - ✅ 正确：`沿 X 轴分量： $f_x = L_{xz}$ ，其中（ $w = 1$ ）。`

2. **内侧严禁留白**：
   - 开头的 `$` 右侧（公式内部开头）与结尾的 `$` 左侧（公式内部结尾）**绝不能有空格**。
     - ❌ 错误：`$ x + y $`
     - ✅ 正确：`$x + y$`

3. **严禁在 Markdown 粗体 `**...**` 内部紧贴包裹 `$ ... $`**：
   - `**$x = 1$**` 或 `**第一列 $[a, c]^T$**` 会导致 CommonMark 的 `**` 定界符与 `$` 定界符发生冲突。
   - **规范**：如需加粗公式，在公式内部使用 `\mathbf{...}` 或 `\boldsymbol{...}`；或者将粗体仅加在中文名词上，并与公式用空格隔开。
     - ❌ 错误：`**$\mathbf{n}$（表面法线）**`
     - ✅ 正确：`$\mathbf{n}$ **（表面法线）**` 或 `- **表面法线** $\mathbf{n}$ ：`

4. **严禁在行内 `$ ... $` 或表格单元格 `| ... |` 中使用带 `\\` 换行的多行环境**：
   - 行内环境（包括普通句子、列表项、表格单元格）中的 `\\` 会先被 Markdown 行内解析器当作转义符吃掉一半变成单个 `\`，导致 `\begin{bmatrix}`、`\begin{cases}` 换行失效或报错。
   - **规范**：
     - 行内表示列向量时，统一使用转置记法： `$\mathbf{P} = [x, y, 1]^T$` 或 `$\mathbf{v} = (x, y, z)^T$`。
     - 凡是需要展示多行矩阵 `\begin{bmatrix}` 或分段函数 `\begin{cases}`，**必须提取到段落外的独立多行 `$$` 块级公式中**（表格中只放矩阵符号如 $T(t_x, t_y)$，矩阵本体放在表格上方的 `$$` 块内）。

5. **严禁对非数学代码使用 `$ ... $`**：
   - 诸如 CMake 生成器表达式 `$<CONFIG:Debug>`、Shell 变量 `$PATH` 等，必须使用反引号代码跨度 `` `$<...>` `` 或代码块包裹。

## 二、块级公式（Block Math：`$$ ... $$`）三条铁律

1. **前后必须各留一个空行**：
   - `$$` 块上方必须有空行，下方也必须有空行。若上方紧贴普通文字而无空行，GitHub 会将 `$$` 合并进上一段落的普通文本流，导致整块公式不渲染并直接暴露源码。

2. **首尾 `$$` 必须各自独占一行（严禁单行 `$$ ... $$`）**：
   - 单行 `$$ \begin{bmatrix} a \\ b \end{bmatrix} $$` 在 GitHub 中会先经过行内转义，把矩阵换行符 `\\` 吞成单个 `\`，导致多行矩阵塌缩成一行。
   - **规范**：开头的 `$$` 与结尾的 `$$` 必须独立成行，且矩阵内部的每一次换行 `\\` 后必须真实换行：
     ```markdown
     利用新增的第 3 列构造平移矩阵：

     $$
     T(t_x, t_y) = \begin{bmatrix}
     1 & 0 & t_x \\
     0 & 1 & t_y \\
     0 & 0 & 1
     \end{bmatrix}
     $$

     其中 $t_x, t_y$ 为平移偏移量。
     ```

3. **列表项或引用块中的块级公式**：
   - 尽量避免在深度缩进的列表或 `>` 引用块内塞入复杂的多行 `$$` 矩阵；优先将大段推导拆分为独立的小标题（`###` / `####`）配合顶格的多行 `$$` 块。

---

## 三、图表与架构可视化规范（禁用 ASCII `text` 字符画）

1. **严禁使用纯文本 ASCII 字符（`┌ ─ │ ╱ ╲ ▲`）拼接几何图或流程图**（因中英文字符不等宽，跨平台必错位）。
2. **流程、状态机、树形结构、管线拓扑**：统一使用带配色高亮的 **Mermaid** 代码块（```` ```mermaid ````）。
3. **几何向量、角度推导、像素网格、内存字节刻度尺**：统一编写标准 **SVG 矢量图**存放于 `docs/assets/` 目录下，并在 Markdown 中通过相对路径 `![图表说明](../assets/xxx.svg)` 引入。
4. **文档写作风格**：遵循“由浅入深”，每篇核心专题开篇先设 **“0. 30 秒核心直觉”**（用生活/物理比喻建立心智模型），再展开主干算法与代码，繁琐的纯代数证明放入文末 **“进阶附录（初学可跳过）”**。
