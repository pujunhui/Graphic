# 软光栅性能瓶颈分析与优化技术

在纯 CPU 实现的软光栅渲染器中，没有 GPU 专用的数千个并发流处理器与高带宽显存。所有坐标变换、图元裁剪、重心求解、纹理采样与像素填充都由 CPU 单核或多核串行执行。如何在有限的 CPU 算力下维持流畅帧率（30~60 FPS），是软光栅设计的核心考验。

本项目在从 `01_drawPoint` 演进到 `19_model` 的过程中，运用并体现了多种经典的图形学优化策略。

---

## 1. 已落地的核心优化策略

### 1.1 算法级优化：完全消除浮点开销（Bresenham 画线）
- **瓶颈**：在屏幕空间逐像素计算 $y = k x + b$ 会产生海量浮点乘加与 `round()` 截断。
- **优化**：Bresenham 算法将累积误差乘以 $2\Delta x$，转化为纯整数误差判别式 $p$ 的增量递推。每步循环仅需 1 次判断与 1~2 次整数加法，计算效率提升数倍。

### 1.2 光栅化级优化：单次叉积复用（Single-Pass Cross Product）
- **瓶颈**：判断点是否在三角形内需要 3 次二维叉积（判断三个子三角形面积符号是否一致）；若采用分离设计，进入插值函数后又需要再次计算 3 次叉积求实际子三角形面积比，导致每个像素重复执行 6 次叉积运算。
- **优化（`Raster::rasterizeTriangle1`）**：
  在循环内只计算一次三个向量的叉积值 $c_0, c_1, c_2$：
  - 其符号用于判断像素是否在三角形内（`c0 <= 0 && c1 <= 0 && c2 <= 0`）；
  - 其绝对值 $|c_1|, |c_2|, |c_0|$ 直接作为面积比分子，除以预计算的总面积 `sumArea` 即得重心权重 $\alpha, \beta, \gamma$。
  **直接砍掉了包围盒内每个像素 50% 的叉积代数开销**。

### 1.3 几何级优化：视锥体裁剪规避无效包围盒遍历
- **瓶颈**：当物体极为接近相机或穿过相机平面时，若不进行近平面裁剪，投影后的顶点坐标可能膨胀至数万像素之外，生成一个覆盖上亿像素的巨大包围盒，导致 CPU 陷入无休止的无效循环，帧率断崖暴跌至 0~1 FPS。
- **优化（`Clipper::sutherlandHodgman`）**：
  在齐次裁剪空间严格对 7 个视锥超平面求交切削，将屏幕外的不可见多边形全部剔除。光栅化面对的永远是裁剪后的合规紧凑多边形。

### 1.4 剔除级优化：背面剔除减半光栅化面片
- **瓶颈**：闭合网格（如立方体、角色、恐龙）有一半的面片背向视点，参与光栅化与片元着色纯属算力浪费。
- **优化（`Clipper::cullFace`）**：
  在投影后依据左手系下法向量的 $Z$ 轴分量符号，在图元进入裁剪和光栅化之前将其丢弃，直接减少了全场景约 50% 的像素填充量。

### 1.5 显存与数据局部性优化：交叉式 VBO（Interleaved VBO）
- **瓶颈**：若位置、法线、UV 分别存储在三个独立的内存块中，着色器处理每个顶点时需在三个分散的内存地址之间跳跃读取，极易触发 CPU L1/L2 缓存行缺失（Cache Miss）。
- **优化**：将每个顶点的所有属性打包为单一结构体 `struct Vertex` 连续存储在同一个 VBO 中。CPU 一次 Cache Line（通常 64 字节）填充即可载入整个顶点的全部数据，大幅提升了数据吞吐率。

### 1.6 资源级优化：纹理缓存池去重（Texture Cache）
- **瓶颈**：复杂 3D 资产（如 `aiScene`）包含数十个子网格（`aiMesh`），通常多个子网格共用同一张漫反射贴图。若每个网格独立加载，会导致内存中存在大量重复位图并频繁进行冗余的图片解码。
- **优化（`Model::mTextureCache`）**：
  以贴图路径作为 Key 建立哈希映射表，多网格共享同一个 GPU 纹理 ID，避免了重复解码与显存冗余。

## 2. 现代商业软光栅进阶优化方向（扩展展望）

若希望进一步将本项目软光栅的绘制效率提升 5~10 倍，可引入以下业界高级优化技术：

### 2.1 基于分块（Tile-Based）的光栅化与多线程并行
- **现状**：当前管线在单个主线程中串行遍历包围盒。
- **优化思路**：
  将 $800 \times 600$ 屏幕划分为若干 $16 \times 16$ 或 $32 \times 32$ 的屏幕图块（Tiles）。利用多线程任务队列（如 `std::thread`、OpenMP 或轻量线程池），各工作线程独立并发光栅化属于自己图块的图元，完全杜绝线程间竞争。同时每个图块的深度缓冲能完整放进 CPU L1/L2 缓存中。

### 2.2 SIMD 向量化指令集加速（SSE / AVX2）
- **优化思路**：
  - 4 维齐次坐标的向量点积、矩阵相乘天然契合 128 位 SSE 寄存器（`_mm_mul_ps`, `_mm_add_ps`），单条指令并发完成 4 个 `float` 运算。
  - 在光栅化内层循环中，利用 AVX2（256 位寄存器）一次性并行处理 $2 \times 4 = 8$ 个像素的内外测试与重心坐标计算，理论吞吐量提升 4~8 倍。

### 2.3 提前深度测试（Early-Z）
- **现状**：当前管线先执行片元着色器（`fragmentShaderStage`），计算出颜色后才执行 `depthTest`。如果一个像素被后续更近的物体覆盖，之前片元着色器执行的纹理采样和光照计算全部被浪费。
- **优化思路**：
  在不修改片元深度（无 `discard` / `gl_FragDepth`）的前提下，将 `depthTest` 移至片元着色器**之前**。若片元被已有物体遮挡，直接跳过漫反射贴图采样与光照点积计算，显著降低 Overdraw 造成的开销。
