# CMake 工程构建与实践指南

本文档系统梳理本项目所涉及的 CMake 现代化构建知识、依赖管理与工程配置规范。

---

## 1. 工程基本配置

### 1.1 最低版本要求与工程定义
```cmake
cmake_minimum_required(VERSION 3.12)
project(Graphic)
```
- `cmake_minimum_required(VERSION 3.12)`：指定构建所需的最低 CMake 解释器版本，确保语法与内置策略（Policies）一致。
- `project(Graphic)`：定义项目名称，自动生成变量 `${PROJECT_NAME}`、`${PROJECT_SOURCE_DIR}`、`${PROJECT_BINARY_DIR}` 等。

### 1.2 C++ 标准与编译器标志
```cmake
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} /utf-8")
```
- `CMAKE_CXX_STANDARD 17`：启用 C++17 标准（支持结构化绑定、`std::clamp`、`std::byte` 等语言特性）。
- `/utf-8`：MSVC 编译器专用标志，强制将源文件字符集和执行字符集均设置为 UTF-8，杜绝在 Windows 平台下中文注释或宽字符代码编译报 `C4819` 警告或字符串乱码。

## 2. 静态资源管理与拷贝指令

在可执行文件运行时，往往需要读取相对路径下的资源（如纹理图片 `assets/textures/`、3D 模型 `assets/model/` 以及第三方动态链接库 `.dll`）。
```cmake
file(GLOB ASSETS "./assets" "./thirdParty/assimp/bin/assimp-vc143-mtd.dll")
file(COPY ${ASSETS} DESTINATION ${CMAKE_BINARY_DIR})
```
- `file(GLOB ...)`：匹配工程根目录下的资源目录与 DLL 文件路径列表存入变量 `ASSETS`。
- `file(COPY ... DESTINATION ...)`：在 CMake 配置生成阶段（Configure / Generate），将指定的文件或文件夹完整拷贝至构建输出根目录 `${CMAKE_BINARY_DIR}`。这使得可执行程序无论是从命令行启动还是从 Visual Studio 本地调试器（工作目录为构建目录）启动，都能以相对路径 `"assets/..."` 直接访问资源，无需硬编码绝对路径。

## 3. 模块化工程与子目录管理

本项目采用模块化拆分架构，根目录通过 `add_subdirectory` 接入各功能子模块：
```cmake
add_subdirectory(application)
add_subdirectory(gpu)
add_subdirectory(gpu_old)
add_subdirectory(thirdParty)
```

每个子目录内均包含独立的 `CMakeLists.txt`，分别负责编译静态库（Static Library）：
- `application`：窗口封装、相机、图片加载与模型数据结构，生成静态库 `app`：
  ```cmake
  add_library(app STATIC application.cpp camera.cpp image.cpp model.cpp)
  ```
- `gpu_old`：阶段一基础光栅化渲染器，生成静态库 `gpu_old`：
  ```cmake
  add_library(gpu_old STATIC gpu.cpp raster.cpp frameBuffer.cpp)
  ```
- `gpu`：阶段二现代软光栅可编程管线，生成静态库 `gpu`：
  ```cmake
  add_library(gpu STATIC
      gpu.cpp raster.cpp frameBuffer.cpp bufferObject.cpp vao.cpp texture.cpp shader.cpp clipper.cpp
      shader/defaultShader.cpp shader/textureShader.cpp shader/lightShader.cpp
  )
  ```
- `thirdParty`：第三方库集成（导入 Assimp 静态/动态库）：
  ```cmake
  add_library(assimp STATIC IMPORTED)
  set_target_properties(assimp PROPERTIES
      IMPORTED_LOCATION "${CMAKE_CURRENT_SOURCE_DIR}/assimp/lib/assimp-vc143-mtd.lib"
      INTERFACE_INCLUDE_DIRECTORIES "${CMAKE_CURRENT_SOURCE_DIR}/assimp/include"
  )
  ```

## 4. 目标生成与链接依赖管理

### 4.1 可执行目标定义与阶段库链接
根目录为 19 个独立实例分别配置编译目标：
```cmake
# 阶段一示例（01 ~ 09）：链接基础光栅化库 gpu_old
add_executable(01_drawPoint "01_drawPoint.cpp")
target_link_libraries(01_drawPoint app gpu_old)

# 阶段二示例（10 ~ 19）：链接现代可编程管线库 gpu
add_executable(10_vao "10_vao.cpp")
target_link_libraries(10_vao app gpu)

# 模型加载示例（19）：除基础模块外，通过 app 内部传递链接 assimp
add_executable(19_model "19_model.cpp")
target_link_libraries(19_model app gpu)
```

### 4.2 依赖传递性（Target Visibility）
在现代 CMake 中，通过控制属性的传递性管理头文件路径与库依赖：
- `PRIVATE`：仅当前目标自身可见，不向依赖方传递。
- `INTERFACE`：当前目标自身不使用，仅作为接口供链接此目标的上层使用者继承。
- `PUBLIC`：当前目标自身使用，且自动向所有依赖它的上层目标传递。
例如，`app` 库依赖 Assimp，设置 `target_link_libraries(app PUBLIC assimp)` 可确保依赖 `app` 的 `19_model` 自动获得 Assimp 的头文件搜索路径与符号解析，无需重复声明。

## 5. Visual Studio 与 CMake 协同开发

本项目深度适配 Visual Studio 2022 的 **Open Folder（打开文件夹）** CMake 模式：
1. 开发者直接用 VS 2022 打开项目根目录，VS 自动识别根 `CMakeLists.txt`。
2. VS 顶部工具栏自动生成所有 `add_executable` 声明的启动项下拉菜单（`01_drawPoint` ~ `19_model`）。
3. 选择任意目标直接按下 `F5` 即可完成即时编译、符号调试与单步追踪。
